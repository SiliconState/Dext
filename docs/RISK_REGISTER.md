# Dext open risk register

This register tracks open non-documentation risks. `docs/index.html` is the canonical main technical documentation and is updated in the same change as behavior; documentation drift is therefore prevented by project policy rather than recorded here.

Priorities: **P1** needs planned mitigation before a stronger security/reliability claim or affected release; **P2** needs an owned control and review trigger; **P3** is accepted unless exposure changes. Likelihood is assessed for the stated exposure, not for every Dext installation.

| ID | Profile · priority | Likelihood | Impact | Confidence | Open exposure and evidence | Current controls | Remediation · owner · review trigger |
|---|---|---|---|---|---|---|---|
| R-001 | Security · platform · P1 | High on affected hosts | High | High | Windows has no kernel filesystem sandbox for shell/external subprocesses; Linux without Landlock and macOS without `sandbox-exec` also fall back to native guards. Evidence: `src/sandbox.rs::describe` and command construction. | Explicit approval profiles; native path validation; credential scrubbing; startup/doctor warning; Windows Job Objects bound process lifetime; WSL recommended for Windows confinement. | Add a supported Windows restricted-token/AppContainer boundary and a fail-closed option for unavailable confinement · runtime/security owner · review before claiming equivalent cross-platform sandboxing or changing sandbox fallbacks. |
| R-002 | Security · recovery · P1 | Low in a quiescent trusted workspace | High | High | Checkpoint restore uses path-based Git/filesystem operations after preflight. A hostile or racing same-user process can replace directories and cause redirected or partially applied multi-path restores. Evidence: `SECURITY.md` concurrent restore limitation and `src/git_checkpoints.rs`. | Operation lock; ref/manifest validation; symlink/hardlink rejection; all-path preflight; owner-private sidecars; preview; checkpoint ref retained. | Use descriptor-relative no-follow traversal and a transactional restore plan, or perform restore in an isolated staging tree · recovery owner · review on every restore-path change or concurrency incident. |
| R-003 | Security · state · Windows · P1 | Medium | High | High | Windows ACL ownership/write safety is not evaluated for `auth.json` or `providers.json`. A permissive ACL can expose credentials or code-execution-sensitive provider state. Evidence: `AuthStoreFileSecurity::WindowsAclNotEvaluated` and Unix-only ownership/mode checks in `src/provider.rs`. | Regular-file and symlink checks; byte/size/schema bounds; fixed user-state location; doctor states auth ACLs are not evaluated. | Inspect owner SID and writable ACEs with Windows security APIs; reject unsafe catalogs and repair auth ACLs on a validated handle · provider/security owner · review before strengthening Windows state-integrity claims. |
| R-004 | Reliability · process lifecycle · P2 | Low accidental; medium for adversarial commands | Medium | High | On Unix, a child that deliberately creates a new session/process group can escape Dext's group cleanup and survive an atomic bash call. Evidence: explicit `setsid` advisory in `src/tool_policy.rs` and `DEXT.md`. | Dedicated session/process group; TERM/KILL cleanup after exit/timeout/interrupt; warnings for `setsid`, `nohup`, `disown`, and backgrounding; OS supervisor guidance for intended persistence. | Add cgroup/supervisor-backed containment where available, or document/enforce a fail-closed process policy for confined profiles · runtime owner · review on orphan-process reports or process-runner changes. |
| R-005 | Reliability · provider transport · P2 | Medium with broken or hostile endpoints | Medium | High | Connect, first-header, and idle deadlines do not impose an overall turn duration. A peer can keep a response alive indefinitely by sending valid chunks just before each idle deadline. Evidence: per-chunk timeout reset in `read_provider_body_limited` and `Agent::read_stream_next_chunk`. | Connect/first-byte/idle deadlines; response/frame/body caps; output-token requests; user interrupt; bounded retry counts. | Add an optional total request/turn deadline with separate local-provider defaults and diagnostics · provider owner · review after long-running-stream incidents or timeout-policy changes. |
| R-006 | Security · packs · same-user concurrency · P2 | Low | High | Medium | Active shelf helpers and native user-pack mutation destinations are validated before path-based execution or replacement. A hostile process running as the same OS user can replace a helper, pack marker, or directory after validation; user packs may also receive narrowly declared credentials. Evidence: `active_pack_helper_invocation` in `src/main.rs`, pack-root validation in `src/session.rs`, and atomic application in `src/mutation_preview.rs`. | Shelf-only discovery; project declarations ignored; provider credential names excluded; canonical parent checks; regular `PACK.md` required for external native mutations; destination/parent revalidation; atomic file replacement; direct-helper grammar; output redaction; same-user processes are outside the intended isolation boundary. | Use descriptor-relative no-follow traversal and execute/replace from validated handles where supported, or copy helpers/mutations through a private immutable staging location · extensions/security owner · review when credential-bearing helpers, user-pack mutation scope, or shelf execution changes. |
| R-007 | Reliability · TUI · Windows · P2 | Medium | Medium | High | Real-PTY TUI smoke tests run on Unix only; Windows CI compiles/tests the code and process lifecycle but does not exercise an interactive ConPTY/Git-Bash terminal. Evidence: `.github/workflows/ci.yml` and `release.yml` skip `tui_smoke` on Windows. | Cross-platform unit tests; Windows CI build/release tests; stdout-based TUI detection; manual Windows use; Unix PTY regression suite. | Add a deterministic ConPTY or Git-Bash interactive smoke harness and require it in Windows CI · TUI owner · review before Windows terminal changes or a Windows support-level increase. |
| R-008 | Release · governance · P2 | Medium until repository settings are verified | High | Medium | Required checks, protected branches/tags, Dependabot security updates, and immutable-release policy are GitHub settings and cannot be guaranteed by source alone. | Read-only workflow permissions; commit-pinned actions; locked builds; audit; four-target release matrix; checksums; attestations; tag/version validation. | Enforce and periodically verify branch/tag protection, required CI, private vulnerability reporting, Dependabot security updates, and immutable releases · repository owner · review before each public release and after settings/admin changes. |
| R-009 | Security · network egress · P1 | Medium for approved shell/process work | High | High | Filesystem sandbox profiles do not restrict outbound network access. An approved arbitrary subprocess can use its own network client and is not subject to the built-in `http` tool's destination checks. Evidence: `SECURITY.md` runtime safety notes and `src/sandbox.rs`. | Approval gates; command-risk classification; credential-shaped environment scrubbing; built-in `http` blocks local/private/link-local/metadata targets unless narrowly opted in. | Add an optional kernel network boundary/allowlist for confined subprocesses, with explicit provider and package-manager exceptions · sandbox/security owner · review before claiming network confinement or handling untrusted repositories with outbound-sensitive data. |
| R-010 | Privacy · local recovery · P3 | Low with normal Git push; medium with mirror/backup sharing | Medium | High | Checkpoint refs and owner-private sidecars may retain sensitive file content. Mirroring `refs/dext/*`, copying the full repository metadata, or sharing state backups can disclose it. Evidence: checkpoint storage in `src/git_checkpoints.rs` and warnings in `SECURITY.md`. | Sidecars are owner-private on Unix; `.dext/` is locally excluded; automatic retention is 20 checkpoints/seven days; normal Git pushes do not include hidden refs; docs warn against mirror-pushing Dext refs. | Add an explicit sensitive-checkpoint inventory/prune workflow and optional checkpoint disable/exclude patterns · recovery/privacy owner · review when retention, backup, or ref publication behavior changes. |

## Review protocol

- Update an entry in the same change that alters its controls, evidence, likelihood, impact, confidence, owner, or status.
- Close an entry only with a linked implementation and verification result; retain the ID in release notes or commit history rather than a permanent closed-item table here.
- Add newly verified residual risks during security, release, provider, process, recovery, or platform reviews. Do not add documentation-drift entries; update `docs/index.html` and the relevant focused guide in the behavior change itself.
